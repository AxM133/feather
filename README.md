# Feather — учебный React-проект

Одностраничный лендинг-каталог мебели, сделанный как практика React. Проект повторяет сайт сервиса аренды мебели Feather: показывает секции главной страницы, товары-бестселлеры, отзывы, проверку зоны доставки и корзину.

## Что можно попробовать

- Посмотреть адаптивную главную страницу и мобильное меню.
- Перейти к секциям по ссылкам в шапке.
- Открыть форму **Check if We Deliver** и проверить американский ZIP-код. Поддерживаются зоны New York City, Los Angeles и San Francisco.
- Добавить товар из блока **Shop our Bestsellers** в корзину. Счётчик корзины сохраняется в `localStorage`, поэтому не пропадает после перезагрузки страницы.
- Пролистать отзывы: карусель листается кнопками и автоматически переключается, пока на неё не наведён курсор.
- Подписаться на рассылку. Сейчас это имитация запроса с задержкой, без реального сервера и сохранения email.

## Стек

- React 19
- Vite 8
- Tailwind CSS 4
- React Icons
- json-server — локальный REST API для каталога
- ESLint

## Быстрый запуск

Нужен Node.js (рекомендуется актуальная LTS-версия) и npm.

```bash
git clone <адрес-репозитория>
cd feather
npm install
```

Создайте в корне файл `.env.local`:

```env
VITE_API_URL=http://localhost:3001
```

В первом терминале запустите API с товарами:

```bash
npm run server
```

Во втором — приложение:

```bash
npm run dev
```

Vite выведет адрес сайта в терминале (обычно `http://localhost:5173`).

Без `VITE_API_URL` или без запущенного `json-server` сама страница откроется, но в блоке бестселлеров появится ошибка загрузки — это ожидаемо: товары запрашиваются по API.

## Как приложение собирается

Точка входа — `src/main.jsx`. Она создаёт React-корень и рендерит `App` из `src/app/App.jsx`. Сейчас `App` выводит только `HomePage`.

```text
main.jsx
  └── app/App.jsx
        └── pages/Home/HomePage.jsx
              ├── widgets/Header
              ├── секции главной страницы
              │     ├── entities (карточки товаров, комнат, отзывов)
              │     └── features (добавление в корзину, доставка, подписка)
              └── widgets/Footer
```

Порядок секций главной можно увидеть и менять в `src/pages/Home/HomePage.jsx`: Hero → комнаты → информационные и промо-блоки → бестселлеры → отзывы → пресса → финальный CTA.

## Структура папок

Проект организован по мотивам Feature-Sliced Design: код разделён не только по типу файлов, а по ответственности.

```text
src/
├── app/             # корневой компонент и глобальные стили
├── pages/Home/       # страница Home и контент её секций
├── widgets/          # большие составные блоки: Header, Footer
├── features/         # пользовательские действия
│   ├── add-to-cart/
│   ├── check-delivery/
│   └── subscribe-newsletter/
├── entities/         # предметные сущности и их UI
│   ├── product/
│   ├── cart/
│   ├── room/
│   └── review/
└── shared/           # переиспользуемые UI, хуки, утилиты, API-конфиг и изображения

server/db.json        # данные локального json-server
public/images/        # изображения, которые отдаёт API в поле image
```

Импорт вида `@/shared/ui` означает `src/shared/ui`: алиас `@` задан в `vite.config.js` и `jsconfig.json`.

## Откуда берутся данные

| Данные | Источник | Как используются |
| --- | --- | --- |
| Бестселлеры | `server/db.json` → `GET /products?bestseller=true` | `getBestsellers` загружает данные, а `useBestsellers` хранит товары, загрузку и ошибку. |
| Комнаты | `src/entities/room/model/rooms.js` | Статичный массив для карточек Shop by Room. |
| Отзывы | `src/entities/review/model/reviews.js` | Статичный массив для карусели. |
| Зоны доставки | `src/features/check-delivery/config/zones.js` | Проверяется первые три цифры пятизначного ZIP-кода. |
| Тексты и изображения секций | `src/pages/Home/config/content.js` | Контент отделён от JSX-компонентов. |

## Важные учебные примеры

- `useBestsellers` показывает типичный сценарий работы с API через `useEffect`: загрузка → успешные данные или ошибка → снятие состояния загрузки.
- `cartStore` — небольшой внешний store. `useCart` подписывается на него через `useSyncExternalStore`, а данные сериализуются в `localStorage`.
- `useAddToCart` добавляет товар и на 1,6 секунды меняет состояние кнопки на подтверждение.
- `useCheckDelivery` нормализует ввод, проверяет длину ZIP-кода и ищет подходящую зону.
- `Modal` использует React Portal, закрытие по Escape, блокировку прокрутки страницы и начальный фокус в диалоге.
- `Carousel`, `Reveal`, `useInView` и хуки прокрутки отвечают за интерактивность и анимации. При `prefers-reduced-motion` анимации почти отключаются.

## Что пока является заглушкой

- У корзины есть только добавление и счётчик: отдельной страницы корзины, изменения количества и оформления заказа пока нет.
- Форма рассылки успешно отвечает после искусственной задержки в `features/subscribe-newsletter/api/subscribe.js`; email никуда не отправляется.
- Часть ссылок с `href="#"` — элементы макета без целевых страниц.
- `json-server` — только локальная учебная база, не production-бэкенд.

## Куда развивать проект

1. Добавить маршрутизацию и страницы каталога, товара и корзины.
2. Заменить `json-server` и заглушку подписки настоящим API.
3. Расширить `cartStore`: удаление, изменение количества, итоговая стоимость и оформление заказа.
4. Добавить тесты для утилит ZIP-кодов, API-хуков и корзины.
5. Вынести адрес API в `.env.example`, чтобы его было проще настроить после клонирования.
